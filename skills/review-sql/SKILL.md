# review-sql

## 目的

sql ファイル / スクリプトをレビューし、可読性、保守性、SQL dialect への適合性を評価する。

## レビュー手順

- 対象の SQL dialect を、設定ファイル、既存コード、ユーザーの指示から確認する
- 対象コードだけでは判断できない事項を、推測で断定しない
- 明示的な修正依頼がない場合、レビュー結果を提示してから修正可否を確認する

## レビュー項目

### capitalisation の一貫性

`keyword`、`identifier`、`function`、`literal`、`type` ごとに、大文字と小文字の使い分けが一貫していることを確認する。

`identifier` は、同じオブジェクトまたは論理列において、定義、alias、CTE の出力、後続クエリからの参照の間で、意図的な改名を除いて表記を統一する。

既存コードまたはプロジェクト規約がある場合は、その規則を優先する。

### indent

インデント幅と配置が一貫していることを確認する。

### CTE

以下の条件を満たしているか確認する。

#### 分割単位

- CTE は、意味ある中間データの単位で分割されている
- 中間データの単位は、抽出 / 結合 / 集計などの処理境界を目安とする
- 責務の異なる処理を単一の CTE に過度に混在させていない

#### CTE 名

- CTE 名より「保持するデータ」または「処理結果」を類推できる

#### CTE コメント

- 各 CTE の直前には、原則として 120 文字以内のコメントが記載されている
- コメント単体で情報として完結しているものとなっている
- 原則として、以下の要素が含まれている
  - 入力: 参照するテーブル / CTE
  - 処理: CTE の責務にあたる主要な処理内容
  - 出力: 作成する CTE / 後続で使う主な列
- 機械的に情報を列挙したものでなく、自然な日本語となっている

#### 記述順序

- データ加工の流れを追えるよう、上から順に記述されている

#### 再帰 CTE

- 再帰 CTE では、起点、再帰方向、停止条件、循環の可能性を確認する

#### 最終メインクエリ

- 最終メインクエリは、可能な限り「最終出力の射影」に限定する
- 複雑な結合 / 集計 / 導出が集中している場合、CTE へ分離することで理解しやすくならないか確認する

### サブクエリ

- サブクエリは、局所的で単純な処理に限り利用する
- 処理結果に名前を付けることで理解しやすくなる場合、CTE を採用する

## コードの更新

- ユーザーが明示的に依頼または同意した変更だけを行う
- レビュー対象外の変更や、必要性のないリファクタリングを行わない
- SQL の意味や実行結果を変える可能性がある変更は、その影響を説明する
